## v0.1.0（2026-11-01）— 首个可用版本

**备份**：`version/20261101-v1/`（package.json、README.md、cordis.patch.yml、index.js、client.js）

### 变更说明
- **host 半身**（`lib/index.js`）：webServer 前缀路由 `/@lanbaolu/dsh-composer-butler/api`，提供
  `/state`（隐藏清单读写，落 `state.json`）、`/rules`（特征表，落 `rules.json`）、
  `/scan`（DOM 侦察快照，落 `scan.json`）、`/info`；注册会话内查询工具 `composer_butler_status`。
- **client 半身**（`lib/client.js`）：手写 `window.__ModuleLoader__.load` bundle，**零构建**，
  只依赖 shell 提供的 `react`。在 `conversation.input.right` 挂「⋯」按钮 + 原生 DOM 面板，
  逐项开关、同名标「重复」、含「重新扫描 / 全部恢复 / 关闭」。
- **隐藏机制**：官方 renderer 的 `SlotOutlet` 渲染 `<div data-slot=… style="display:contents">`，
  正常路径下错误边界不额外包 DOM ⇒ 锚点直接子元素即各插件根节点。给它打
  `data-composer-butler-hidden` + 注入 `[data-composer-butler-hidden]{display:none!important}`。
  官方**没有**逐 entry 可见性属性，这是唯一可行路径。
- **状态持久化**：`localStorage` 即时写 + 上报 host 落盘（换浏览器/清缓存可从 `/state` 补回），
  满足「设置实时自动保存」规则。
- **自愈**：`MutationObserver`（60ms 节流）在切会话/插件热装配导致 DOM 重建后重新套用隐藏。

### 本次会话内修的问题（v0.1.0 开发过程中）
1. `inject` 漏声明 `tools` → 注册工具时崩、entry 变 `[no-fiber]`（host ✗）。已补为 `['webServer','tools']`。
2. 数据目录落在 `lib/` → 改为包根（数据不与代码混放）。
3. **管家按钮会被自己扫进列表**，用户误关即再也打不开面板 → 加 `data-composer-butler-self`
   标记，`scanControls()` 用 `closest()` 排除自身。
4. **控件身份随状态漂移**：PUA 的 aria-label 是「PUA（当前会话已关闭）」↔「（当前会话已开启）」，
   整串做 key 会导致切换会话后隐藏失效 → 新增 `stableName()` 取分隔符前前缀归一。
   分隔符集合最终定为 `[，,、（(：:—–]`，**刻意不含 ASCII 连字符**（否则 `hold-to-dictate`
   被压成 `hold` 造成误碰撞）。7 条真实文案单测全通过。

### 验证情况
- ✅ `npx dsh-plugin-standard@2 --json` → **0 FAIL**（仅 1 条 WARN：无 typecheck/build/test/pack 脚本，
  纯 JS 零构建插件本不适用）。
- ✅ `node --check` 两个半身语法通过。
- ✅ host 半身用 mock ctx 跑 `apply()` 成功注册 2 个 effect（api + status tool）。
- ✅ `dev_inject_plugin` → **host ✓ / client ✓**；`dev_reload_package` 热重载成功。
- ✅ API 实测：`/info` 返回正确 dataDir（包根）、`/state` 返回 `{hidden:[]}`。
- ✅ `dev_uninject_plugin` 回归：entry 卸载、registry 清理、client 模块表清理（junction 删除
  有缺陷，见下）。
- ⏳ **待用户浏览器内验证**：`scan.json` 尚未生成，说明已打开的 GUI 页面还没加载新 client
  （注入只更新服务端模块表，不推给已开页面）。需刷新一次页面后确认「⋯」出现、面板列出控件、
  逐个开关生效、刷新后状态保持。

### 顺带发现的上游缺陷（本机环境）
- **dsh-super-injector 在桌面端 profile 错位**：`profileNodeModules` 默认硬编码
  `profiles/web/node_modules`，而本机运行的是 `desktop` profile ⇒ junction 建到 web、
  `loader.create` 解析不到模块 ⇒ 注入必 `[no-fiber]`。
  已给磁盘文件打补丁（按 `config > DSH_PROFILE > 从自身路径反推 > 兜底 web` 解析），
  但**注入器自重载不生效**（`dev_reload_package dsh-super-injector` 报
  「缓存中无匹配且磁盘降级失败」），需重启 DSH 才吃到补丁。
  当前会话的临时解法：手工在 `profiles/desktop/node_modules/@lanbaolu/` 建 junction。
- **注入器质量红线在 Windows 下 `spawn EINVAL`**：`runVerify()` 找不到本地
  `dsh-plugin-standard` 时回退 `execFile("npx.cmd", …)` 必挂。已把校验包复制到
  `@lanbaolu/dsh-super-injector/node_modules/dsh-plugin-standard` 绕过（无需改码）。
- **slot 白名单过窄**：注入器 `KNOWN_SLOTS` 缺 `conversation.input.left/right` 等官方真实存在的
  输入框槽位，会把合法插件误判为坏骨架。已补 8 个（同样需重启生效）。
- **卸载不删 junction**：`dev_uninject_plugin` 报「Path is a directory」，需手工
  `rmdir`（必须用 rmdir 删链接本身，**绝不能递归删**，否则伤及 G 盘源目录）。

### 关键技术决策
| 问题 | 决定 | 理由 |
|---|---|---|
| 源码放哪 | 原地留在 `G:\DSH\dsh-plugins\dsh-composer-butler`，不搬到 `G:\Python_Code` | 用户明确选择「不用移动了」；插件在该目录已被注入器登记，搬走会让 junction 失效 |
| 运行期数据要不要上传 | 不上传 | `state.json` 是使用者个人隐藏清单、`scan.json` 含本机界面快照，属隐私；已在 `.gitignore` 拦死 |
| 中文 description 怎么提交 | 先写 UTF-8 无 BOM JSON 文件，再 `gh api --input` | 直接当命令行参数传，中文会被 PowerShell → 进程边界转义成 `?`（mame_autopress 踩过） |
| 版本号要不要升 | 不升，保持 v0.1.0 | 插件代码零改动，只改文档/仓库；升版本会让使用者以为行为变了 |
| README 里写不写本机盘符 | 不写具体盘符，用占位符 | 对读者无意义、会过期；只在通用 profile 路径示例里保留 `C:\Users\<你>\.dsh\...` 这种标准位置 |
